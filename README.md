# Localy

Localy — CRM и платформа лояльности для малого офлайн-бизнеса. В MVP есть онбординг, касса с QR, CRM, акции, рассылки, публичный сайт с записью, аналитика, тарифы и админ-панель.

## Запуск

Требуется Node.js 20.9 или новее.

```bash
npm install
npm run dev
```

Откройте <http://localhost:3000>. В локальном режиме детерминированные демо-данные хранятся в `data/localy.json`.

## Демо-вход

Только для локальной демонстрации начальный пароль аккаунтов — `Localy2026`. На размещённом окружении задайте отдельный `LOCALY_DEMO_PASSWORD` и не публикуйте его.

- `owner@localy.kz` — владелец
- `admin@localy.kz` — администратор бизнеса
- `marketing@localy.kz` — маркетолог
- `cashier@localy.kz` — кассир
- `platform@localy.kz` — админ Localy

## Проверка

```bash
npm run lint
npm run typecheck
npm run build
npm run smoke:e2e
```

`smoke:e2e` запускает изолированный production-сервер и проверяет основной сценарий в headless Chrome: онбординг, SMS-код в локальном тестовом режиме, QR, кассу, бонусы, CRM, рассылки, роли, админку и публичную заявку без несанкционированной клиентской сессии.

## Production

1. Примените миграции из `supabase/migrations`.
2. Скопируйте переменные из `.env.example` в секреты хостинга.
3. Установите `LOCALY_REPO=supabase`, URL Supabase и server-only `SUPABASE_SERVICE_ROLE_KEY`.
4. Задайте случайные `LOCALY_SESSION_SECRET`, `LOCALY_OTP_SECRET` и 32-байтный base64 `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY`.
5. Подключите HTTPS SMS webhook через `LOCALY_SMS_WEBHOOK_URL`.

Supabase хранит состояние в закрытой RLS-таблице `localy_state`. Записи защищены номером версии: при одновременном изменении второй сервер получает явный конфликт вместо тихой потери данных. JSON-режим предназначен только для локальной разработки; на Railway и Vercel приложение откажется запускаться с ним.

Startup-проверка немедленно завершит неверно настроенный hosted-инстанс, пока не заданы Supabase, HTTPS SMS webhook, production-пароль и все криптографические секреты.

Пароли хешируются salted scrypt. Старые SHA-256-хеши поддерживаются только для миграции и автоматически заменяются после успешного входа. Клиентская сессия выдаётся исключительно после проверки одноразового SMS-кода; публичные заявки и записи её не создают. На вход, OTP, публичные формы и AI-генерацию установлены лимиты запросов.
